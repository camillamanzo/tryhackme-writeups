# Defensive Security

## 🛡️ Overview

The **Blue Team** is responsible for preparing and proactively protecting an organisation's IT infrastructure — both preventing and detecting intrusions.

### Core Tasks

| Task | Description |
|------|-------------|
| **Cyber Security Awareness** | Training users to recognise and avoid threats |
| **Asset Management** | Documenting and inventorying systems within the org to know what needs protecting |
| **Preventative Security** | Firewalls and IPS as the first line of defence |
| **Logging & Monitoring** | Essential for detecting threats and intrusions in progress |
| **Frameworks, Policies & Procedures** | Ensuring devices and systems are used appropriately across the org |

---

## 🏢 SOC — Security Operations Centre

A team that **monitors the network and its systems** around the clock.

### SOC Focus Areas

| Area | Description |
|------|-------------|
| **Threat & Vulnerability Awareness** | Keeping up to date with emerging threats and CVEs |
| **Policy Violations** | Monitoring adherence to internal security policies |
| **Unauthorised & Illegal Activity** | Establishing a baseline of acceptable behaviour and detecting deviations |
| **Intrusion & Breach Detection** | Detecting active intrusions and coordinating response |

---

## 🔬 Digital Forensics

The application of **forensic science processes to digital systems** — used to investigate incidents, collect evidence, and understand what happened.

### Information Types Analysed

| Source | What It Reveals |
|--------|----------------|
| **File System** | Installed programs, created, modified, overwritten or deleted files |
| **System Memory** | Malicious programs running in memory and how they operate |
| **System Logs** | Record of what happened on the system (logins, errors, events) |
| **Network Logs** | Traffic that traversed the network — connections, data transfers, anomalies |

---

## 🚨 Incident Response

How organisations **manage and recover from security events**.

### IR Process (PDRP)

| Phase | Description |
|-------|-------------|
| **Preparation** | Creating the necessary resources, playbooks and frameworks to handle incidents before they occur |
| **Detection & Analysis** | Using tooling and processes to identify and understand incidents |
| **Containment, Eradication & Recovery** | Limiting the impact, removing the threat, and restoring normal operations |
| **Post-Incident Activity** | Reviewing how the incident was handled and identifying how it could have been prevented |

```
Preparation → Detection & Analysis → Containment/Eradication/Recovery → Post-Incident Review
     ↑                                                                           |
     └───────────────────── Lessons learned fed back ────────────────────────────┘
```
